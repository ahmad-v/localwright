## Known gaps

Only two crates; settings schema is a library API, not automatically persisted by UI. Applications can opt into persistent theme, scale, toolbar visibility, enhanced focus outlines, shortcuts and a validated 20–70% sidebar ratio. The basic `run` entry point remains session-local unless the user explicitly saves a workspace session. Session files are unencrypted and can contain paths, parameters and draft text; they exclude result payloads and loaded table data. Session restore appends tabs, validates operation ids and does not execute operations. Table filtering searches only cells already loaded by the application; it does not stream or query source files. Detachable panels, system theme detection, icon pack, localization, screen-reader verification and complete accessibility, choosing Viridis or Cividis as the default sequential map, Okabe-Ito permission, and broader diverging and accessible qualitative palette coverage remain open. The new engine runtime does not provide OS sandboxing or hard resource quotas.

The Localwright merged baseline passed its current Linux x64, Linux ARM64, Windows x64, Windows ARM64 and Apple Silicon jobs, plus Quick and Integration checks. This verifies compilation and the automated fixtures at that commit; it does not establish every studio's current native acceptance, physical-device behavior or complete GUI accessibility. See [verification evidence](VERIFICATION.md) and [dependency review](DEPENDENCIES.md).

## Private engine runtime increment

`localwright-core::engine` now implements version-1 private engine manifest parsing, application-relative discovery, explicit absolute trusted-path resolution, SHA-256 verification, capability registration, health checks, structured argument execution, an allowlisted cleared environment, private temporary working directories, bounded input/output, timeouts, process-group cancellation/cleanup, and an opt-in per-invocation hidden console window on Windows. The runtime deliberately does not claim an OS sandbox or hard CPU/memory quota. Linux engine tests and strict Clippy pass locally; the new Windows launch path is included in the current shared revision and awaits its hosted native matrix. The merged Localwright baseline then passed all five hosted native targets and both Check and Integration workflows; exact job links are recorded in [verification evidence](VERIFICATION.md).

The existing workflow previously ran the full native matrix on every ordinary check. The Localwright quick check is now a single Linux x64 workflow, preserving the `Check / Rust (ubuntu-24.04)` context. The native matrix and separate integration, distribution and security workflows are the next workflow changes in this batch; platform jobs must remain meaningful acceptance gates, not ordinary release builds.
